# Synthetic JTBD — перенос на PS.kz

## Состояние на 21 ноября 2026

Подготовлена самостоятельная сборка интерфейса для HTML/PHP shared hosting. Сайт на PS.kz ещё не загружен, `jtbd.mikh.kz` не переключён. Проверка опубликованного Manus API возвращает HTTP 200 с HTML «Site unavailable due to unpaid billing», а не tRPC JSON. Поэтому работа реального AI пока не подтверждена. Шлюз превращает такой ответ в честную JSON/tRPC-ошибку HTTP 503.

Выбрана гибридная схема: страницы, книга, Research Navigator, учебные артефакты, темы и анимации работают на PS.kz; чат, генерация примеров, генерация Canvas/Job Chain и оценка артефактов остаются на Manus. Manus-проект необходимо сохранить действующим. Оплата PS.kz сама по себе не включает AI Manus. Перенос не является полной автономизацией AI.

## Состав и сборка

Релиз содержит `index.html`, `assets/`, `media/job_chain_diagram_a891f841.png`, `gateway.php`, `gateway-lib.php`, `.htaccess`, `robots.txt`, `release.json`. В релиз не входят исходники книги, `.env`, ключи API, cookies, база данных, OAuth-конфигурация, `node_modules` или source maps. API-ключи не нужны на PS.kz.

Сборку запускать на компьютере разработки с Node/pnpm, не на shared hosting. Для автоматических offline-тестов PHP-шлюза нужен также PHP CLI 8.0+ с cURL, JSON и iconv:

```bash
cd /home/ubuntu/synthetic-jtbd-book
pnpm install
pnpm test
pnpm check
node scripts/build-pskz.mjs /absolute/new-empty-release-directory /absolute/path/job_chain_diagram_a891f841.png
```

Выходной каталог должен быть новым или пустым и находиться вне исходного проекта. Сборщик не очищает занятые каталоги, исключает Manus debug/analytics injection и публичные `VITE_*` секреты. Иллюстрация локализуется только в копии сборки: исходник книги сохраняет Manus storage reference для исходного проекта.

Также исправлена блокировка относительной иллюстрации рендерером Markdown: для книги задан текущий origin и разрешены только изображения из его `/media/` и `/manus-storage/`. Сторонние URL и data-изображения не разрешаются. Содержание книги, hero и дизайн не изменены.

Обычная команда `pnpm build` по-прежнему собирает исходный Manus-проект. В неё добавлено копирование `server/book_content.md` в `dist/book_content.md`: прежде production AI мог работать с краткой резервной строкой вместо исходного контекста. Это изменение вступит в силу на Manus только после новой публикации. Четыре AI-процедуры и их логика не изменены.

## PHP и ограничения шлюза

Требуются PHP 8.0+ с расширениями cURL, JSON и iconv, рабочий HTTPS egress к `https://jtbd.manus.space`, Apache mod_rewrite и возможность применять `.htaccess`. Нужно проверить это на PS.kz; локальный тест не заменяет проверку фактического хостинга. Предел времени PHP/веб-сервера желательно не ниже 110 секунд, так как шлюз ждёт upstream до 100 секунд.

Разрешены только `ai.chat`, `ai.generateExample`, `ai.generateArtifacts`, `ai.evaluate`, только POST с `Content-Type: application/json` и единственным query `batch=1`. В batch разрешено 1–4 вызова с непрерывными индексами. Сохраняется существующий tRPC/SuperJSON транспорт `/api/trpc`; произвольного REST API не вводится.

Шлюз проверяет поля, роли, длину текста и историю. Ограничения: максимум 30 сообщений, 12 000 UTF-16 единиц на сообщение, 48 000 на всю историю; контекст генератора 30–5000; артефакт оценки 10–30 000. Нельзя передать URL upstream, роли system, дополнительные поля, meta-преобразования или неизвестный метод. Origin при наличии должен быть ровно `https://jtbd.mikh.kz`; отсутствие Origin не является аутентификацией и допускается для серверных клиентов. При тестировании по HTTP или на другом hostname браузерный Origin будет отклонён — production HTTPS origin нужно сохранить в тестовом клиенте или использовать curl.

Нагрузка ограничена 12 RPC в минуту и 120 в час на адрес посетителя. За Cloudflare это значение заголовка `CF-Connecting-IP`, но только если TCP-соединение пришло с опубликованного адреса Cloudflare (список в `gateway-lib.php`, сверять с https://www.cloudflare.com/ips/); иначе используется `REMOTE_ADDR`, максимум тремя одновременно выполняемыми запросами на шлюз. Пределы учитывают каждый RPC, а не только один HTTP batch. Состояние хранится в закрытом каталоге PHP temp вне document root с `flock`. Не используются X-Forwarded-For и cookies для определения IP. Фактический `REMOTE_ADDR` нужно проверить в конфигурации nginx/Apache PS.kz. Пользователи с одним общим IP делят лимит.

Редиректы upstream отключены, TLS проверяется, ответ ограничен 1 MiB. Cookies, Authorization, ключи и пользовательские заголовки не пересылаются. Тела запросов самим шлюзом не логируются. HTML со статусом 200 не считается успехом. При недоступности возвращаются русская tRPC-ошибка 503 и `Retry-After: 60`.

**Ограничение безопасности:** эти меры защищают только PHP-шлюз. Сам публичный Manus API остаётся доступен напрямую и не получает глобальные квоты или аутентификацию от этого шлюза. Квоты на upstream следует контролировать отдельно на Manus. Удалять Manus-проект или отзывать его встроенные ключи до замены AI нельзя.

## Загрузка без повреждения других сайтов

1. Войти в Plesk через браузер пользователя и открыть File Manager подписки mikh.kz. Записать фактическую DNS-зону и текущую JTBD-запись для отката.
2. Создать новый изолированный каталог для релиза **вне `httpdocs` mikh.kz и вне корней других приложений**. Через Upload загрузить ZIP, распаковать его, убедиться, что `index.html` и `.htaccess` находятся в корне релиза. Не сбрасывать FTP или системный пароль ради загрузки.
3. Проверить фактические PHP/cURL/iconv/temp/flock. При необходимости создать минимальный временный probe, не выводящий ключи, полный `phpinfo` или переменные среды, и удалить его после проверки.
4. Создать virtual host/subdomain JTBD с отдельным document root и PHP. **Создание субдомена Plesk может автоматически изменить DNS. Не выполнять этот шаг до согласованного момента переключения либо без проверенного способа сохранить текущий CNAME.** Не перезаписывать текущий `mikh.kz` и не изменять другие поддомены.
5. До переключения проверить origin через Host header/`--resolve`, включая `/`, `/book`, `/research`, `/chat`, `/trainer`, PNG, защиту PHP library, неизвестные API и маршруты SPA. Для полноценной проверки AI дождаться восстановления опубликованного Manus backend. Иначе сначала получить явное согласие владельца на временно недоступные AI-функции.
6. Переключить **только JTBD**: прежний `jtbd.mikh.kz CNAME cname.manus.space` заменить на `jtbd.mikh.kz A 195.210.46.55`. CNAME не может сосуществовать с A на одном имени. Не добавлять AAAA без проверки готовности IPv6 origin; не менять NS, MX, основной домен или другие сайты.
7. Выпустить и проверить HTTPS для `jtbd.mikh.kz` через SSL/Let's Encrypt Plesk. Проверить authoritative DNS и сертификат, затем повторить все публичные проверки. HTTPS-редирект включать только после валидного сертификата. Убедиться, что nginx PS.kz не игнорирует нужные Apache rewrites.
8. Удалить загруженный ZIP из публичного document root, временные probes и лишние файлы. Приватный временный файл Plesk-доступа на компьютере разработки удалить после завершения переноса. Пользователю рекомендуется сменить пароль панели, ранее отправленный в чат.

## Откат и дальнейшие обновления

До переключения сохранить старый DNS record и копию предыдущего document root, если он появится. Откат DNS: удалить только новый JTBD A и восстановить `jtbd.mikh.kz CNAME cname.manus.space`. Остальные записи не изменять. Такой откат не исправляет billing Manus: старый адрес сейчас тоже недоступен.

Для обновления PS.kz снова собрать новый релиз, загрузить в отдельный каталог, проверить и переключить document root на него. Не распаковывать вслепую поверх чужого `httpdocs`. Обновления исходного Manus-проекта не синхронизируют PS.kz автоматически. Изменения AI backend публикуются на Manus отдельно; они должны сохранять контракты четырёх процедур. LocalStorage-прогресс сохраняется при том же origin `https://jtbd.mikh.kz`, но не переносится между разными адресами Manus и JTBD.

## Проверки подготовки

На компьютере разработки прошли 77 Vitest-тестов, PHP lint, TypeScript и обе production-сборки. Локальный Apache/PHP подтвердил SPA-маршруты, PNG, запрет supporting PHP/скрытых файлов и корректный JSON503 при billing HTML upstream. Браузерные проверки самостоятельной production-сборки прошли: страницы desktop/mobile, светлая и тёмная темы, reduced motion, учебные артефакты B2B/Job Chain, переключение глав, чтение из localStorage, фактически загруженная иллюстрация и понятная ошибка AI. Горизонтального overflow и ошибок выполнения страницы не обнаружено. Для локального HTTP-теста AI использован Playwright HTTP bridge с production Origin, не ослабляющий защиту самого шлюза.

Визуальная проверка сохраняет существующий дизайн, а не заявляет о новом редизайне. Style-инспектор отмечает многорядные заголовки, малые вторичные подписи и отсутствие фотографий/видео в исходном макете. Эти особенности не менялись при переносе: точный hero, темы и отсутствие видео выбраны пользователем.

Внешняя миграция, проверка фактического PHP PS.kz, DNS cutover, сертификат и успешная AI-генерация **ещё не выполнены**. Успешная локальная сборка или checkpoint не являются доказательством публикации на PS.kz.

## Автоматическая выкладка из GitHub

Workflow `.github/workflows/deploy-pskz.yml` собирает релиз и загружает его на PS.kz при каждом пуше в `main`, который затрагивает `client/`, `shared/`, `server/book_content.md`, `deploy/pskz/`, `scripts/`, `package.json` или `pnpm-lock.yaml`. Запустить вручную можно во вкладке Actions («Run workflow»); флаг `dry_run` показывает, что будет загружено, без изменений на хостинге.

Порядок: тесты и `pnpm check` → сборка `scripts/build-pskz.mjs` → загрузка по FTP(S)/SFTP (сначала все файлы, кроме `index.html` и `.htaccess`, затем они и удаление устаревших файлов) → проверка, что `https://jtbd.mikh.kz/release.json` содержит хеш собранного коммита.

Настройка в GitHub (Settings → Secrets and variables → Actions):

| Имя | Тип | Значение |
| --- | --- | --- |
| `PSKZ_FTP_HOST` | secret | хост FTP/SFTP из Plesk |
| `PSKZ_FTP_USER` | secret | отдельный FTP-пользователь с доступом только к каталогу сайта JTBD |
| `PSKZ_FTP_PASSWORD` | secret | пароль этого пользователя |
| `PSKZ_FTP_DIR` | secret | `/`, если FTP-пользователь создан с домашней папкой сайта JTBD (рекомендуется); иначе путь к document root JTBD |
| `PSKZ_PROTOCOL` | variable, необязательно | `ftp` (FTPS, по умолчанию) или `sftp` |
| `PSKZ_VERIFY_TLS` | variable, необязательно | `no`, только если сертификат FTPS на хосте самоподписанный |

Без секретов `PSKZ_FTP_*` workflow только тестирует и собирает релиз, на хостинг ничего не отправляет. Выкладка использует `mirror --delete` внутри `PSKZ_FTP_DIR`, поэтому каталог должен быть выделен под этот сайт (в Plesk: дополнительная учётная запись FTP с домашней папкой `/jtbd-release-20261121`, тогда `PSKZ_FTP_DIR=/`); каталоги `.well-known`, `cgi-bin`, `error_docs`, `stat` не затрагиваются. Пароли не хранить в репозитории и не отправлять в чат.

Иллюстрация книги: положите `job_chain_diagram_a891f841.png` в `deploy/pskz/media/` и закоммитьте. Если файла нет, workflow скачивает его с действующего сайта, что удобно для первого запуска, но хрупко.

Откат: перезапустить workflow на предыдущем коммите (Actions → Run workflow, выбрав ветку/тег с нужной версией) либо `git revert` и пуш в `main`.
